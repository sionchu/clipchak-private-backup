# 호스팅 이전·백업·광고 운영안

## 현재 구조

- 화면과 API: OpenAI Sites
- 미디어 분석: Render Docker 서비스
- 실제 영상·사진 전송: 원본 플랫폼/CDN에서 사용자 브라우저로 직접 전달
- 소스 백업: 비공개 GitHub 저장소

분석 서버는 작은 JSON만 주고받으므로, 정상적인 직접 연결 경로에서는 영상 크기에 비례한 서버 전송료가 생기지 않는다.

## 이전 가능한 경계

프런트엔드의 분석 서버 주소는 환경 변수로 분리돼 있다. Render를 Fly.io, Railway, Cloud Run, Cloudflare Containers 또는 VPS로 옮길 때 `MEDIA_RESOLVER_ENDPOINT`와 토큰만 교체한다. 미디어 파일 저장소나 사용자 DB가 없어 데이터 마이그레이션 범위도 작다.

## 비용 방어

- 원본/CDN 직접 결과만 허용
- 분석 요청 시간·횟수·결과 개수 제한
- 로그인·비공개 콘텐츠 재시도 금지
- 실패 코드별 성공률을 플랫폼 단위로 집계
- 특정 플랫폼의 차단률이 높아지면 화면에서 일시 점검 상태로 전환

## 광고

초기에는 결과 버튼과 혼동되지 않는 본문 중간 또는 결과 아래의 고정 광고 자리만 사용한다. 다운로드 버튼처럼 보이는 광고, 자동 팝업, 강제 리다이렉트는 사용하지 않는다. 트래픽이 충분해진 뒤 AdFit과 AdSense를 기간별로 비교하고 플랫폼별 성공 전환율과 광고 RPM을 함께 본다.

## 배포 점검

- `pnpm test`와 프로덕션 빌드
- 분석 서버 단위 테스트와 `/health`
- 지원 플랫폼 도메인 인식 테스트
- 공개 샘플 URL 메타데이터 추출
- 반환 URL의 원본 도메인 직접 접근 여부
- 모바일에서 열기·공유 동작
