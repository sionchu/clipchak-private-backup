# 클립착 미디어 분석·트래픽 구조

## 결론

대용량 영상·사진 파일은 `원본 플랫폼/CDN → 사용자 브라우저`로 직접 보내고, 클립착과 분석 서버는 URL 확인과 결과 JSON만 처리하는 구조가 가장 저렴하다.

```text
사용자 → clipchak.kr → 분석 API(게시물 주소만 확인)
사용자 ← 원본 CDN(영상·사진 본문 직접 수신)
```

이 구조에서는 파일착/클립착 호스팅의 전송량이 거의 늘지 않는다. 다만 완전한 브라우저 단독 추출은 현실적으로 어렵다. 소셜 페이지는 CORS, 만료되는 서명 URL, 쿠키, JavaScript 렌더링, 형식별 오디오·영상 결합 때문에 서버 또는 사용자 기기의 네이티브 프로그램이 필요한 경우가 많다.

브라우저의 `fetch()`는 원본 서버가 CORS를 허용해야 응답 본문을 읽을 수 있다. 또한 `<a download>`는 교차 출처 URL에서 다운로드 동작을 보장하지 않으므로 클립착은 새 탭으로 원본을 열고 기기 저장 메뉴를 사용하도록 안내한다. 서비스 워커도 CORS를 우회할 수 없다.

## 권장 2단계 구성

1. 1차: `direct-only`
   - 분석 서버는 `--skip-download`, JSON 출력 또는 직접 URL 출력만 사용한다.
   - 원본 CDN URL과 사진·영상 종류, 품질, 파일명만 반환한다.
   - 클립착은 파일을 프록시하지 않는다.
   - 원본 직접 URL이 없으면 성공으로 가장하지 않고 중계 불가를 안내한다.
2. 2차: 선택적 외부 미디어 서버
   - 오디오·영상 결합이나 강제 다운로드 헤더가 꼭 필요한 플랫폼만 별도 서버로 보낸다.
   - Sites와 분리해 트래픽 상한, 파일 크기 제한, 시간 제한을 적용한다.
   - `MEDIA_ALLOW_PROXY=true`는 비용을 이해한 뒤에만 켠다.

| --- | --- | --- | --- | --- |
| [yt-dlp/yt-dlp](https://github.com/yt-dlp/yt-dlp) | 수천 개 사이트의 영상 메타데이터·원본 포맷 URL 추출 | 썸네일 중심 | URL만 반환하도록 구성 가능 | 영상 분석기의 1순위 기반. Python/FFmpeg 서버가 필요하고 플랫폼 정책을 별도 검토해야 함 |
| [mikf/gallery-dl](https://github.com/mikf/gallery-dl) | 이미지 갤러리·소셜 사진과 여러 장 게시물 추출 | 강함 | `-g`로 직접 URL만 반환 가능 | 인스타그램 사진·캐러셀 분석기의 1순위. 활성 개발은 Codeberg로 이동 |
| [imputnet/cobalt](https://github.com/imputnet/cobalt) | 웹 UI와 미디어 API, 사진·영상 picker | 강함 | redirect도 있지만 tunnel/proxy 응답도 있음 | 빠른 참고·별도 서버 후보. AGPL 조건과 자체 호스팅 필요. Sites 트래픽 0 해법 자체는 아님 |
| [kevinwatt/yt-dlp-mcp](https://github.com/kevinwatt/yt-dlp-mcp) | AI 도구가 로컬 yt-dlp를 실행 | 영상 중심 | MCP가 실행되는 컴퓨터의 회선 사용 | 개발·운영 보조용. 일반 방문자의 브라우저에서 실행되는 제품 백엔드는 아님 |

MCP는 Codex 같은 개발 도구에 기능을 노출하는 통로다. 방문자가 링크를 붙여넣는 실제 웹 서비스의 분석 서버와는 역할이 다르므로, MCP를 설치한다고 사용자 로컬 트래픽 구조가 자동으로 만들어지지는 않는다.

## 플랫폼별 현실적인 조합

- 유튜브: 기술적으로 yt-dlp 메타데이터 모드가 가깝지만 YouTube API 정책과 서비스 약관상 다운로드 제공 위험이 크다. 플랫폼이 명시적으로 허용한 저장 기능과 권리 보유 콘텐츠만 대상으로 제한한다.
- 틱톡: 사진 슬라이드는 cobalt picker 형태 또는 별도 공개 게시물 분석기로 항목별 URL을 반환한다.
- 인스타그램: gallery-dl의 URL 출력 방식이 사진·캐러셀에 적합하다. 로그인 쿠키를 서버에 수집하는 구조는 초기 서비스에서 제외한다.
- 스레드: 위 후보들의 공식 지원이 약해 공개 HTML/메타데이터 전용 어댑터를 따로 유지해야 한다. 로그인·비공개 우회는 하지 않는다.
- 링크드인: yt-dlp에 영상 extractor가 있으나 사진 게시물은 별도 공개 메타데이터 어댑터가 필요하다. LinkedIn Learning과 로그인 전용 자료는 제외한다.

## 비용 방어선

- API 응답은 URL 메타데이터만, 최대 30개 항목
- 입력 도메인 허용 목록
- 요청 빈도 제한과 Turnstile 적용
- 응답 캐시 5~15분(원본 URL 만료 시간보다 짧게)
- 분석 시간 15초 제한
- 프록시 기본 차단
- 프록시를 켜면 1회 파일 크기·일일 총 전송량·사용자별 횟수 제한
- 원본 URL, 쿠키, IP, 파일을 로그에 남기지 않음
